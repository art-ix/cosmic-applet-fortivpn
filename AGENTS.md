# AGENTS.md

Guidance for AI coding agents working in this repository.

## What this is

`cosmic-applet-fortivpn` — a COSMIC panel applet (Rust, `libcosmic`/iced) that toggles
`openfortivpn` through a dedicated systemd unit. See `README.md` for user-facing docs.

```
applet (user) ──D-Bus (zbus)──> systemd ──> cosmic-fortivpn.service ──> /usr/bin/openfortivpn
```

## Layout

| Path | Role |
|---|---|
| `src/main.rs` | entry point, tracing init |
| `src/app.rs` | `cosmic::Application`: panel icon, popup UI, `Message` handling, D-Bus subscription |
| `src/systemd.rs` | zbus proxies (`Manager`, `Unit`), `VpnState`, start/stop, `watch()` |
| `src/localize.rs`, `i18n/` | Fluent i18n (`fl!` macro), `en` fallback + `pl`, `de`, `es`, `it`, `fr` |
| `src/info.rs` | journald tail (`journalctl`), `ppp*` name/IP (`ip`), traffic counters from `/sys/class/net/<if>/statistics`, byte/duration formatting |
| `src/icons.rs`, `assets/icons/` | project-owned SVG icons (24x24, 2 px stroke, `currentColor`) embedded with `include_str!` and rendered as symbolic (theme-coloured) icons; no third-party icon sets |
| `data/` | files installed to the system: `.desktop`, systemd unit, polkit rule |
| `install.sh`, `justfile` | install/uninstall (tarball/source install) |
| `debian/`, `scripts/` | `.deb` maintainer scripts (`postinst`, `prerm`, `postrm`); `build-deb.sh` (cargo-deb) and `test-deb.sh` (Docker, clean Ubuntu 24.04). Package metadata is in `Cargo.toml` `[package.metadata.deb]` |
| `.github/workflows/` | `ci.yml` (fmt, clippy, test), `release.yml` (tag → tarball + GitHub release) |

## Commands

```sh
cargo fmt --check
cargo clippy --locked --all-targets -- -D warnings
cargo test --locked
cargo build --release
```

CI runs exactly these; keep them green. System build deps:
`pkg-config libxkbcommon-dev libwayland-dev libinput-dev libudev-dev`.

## Rules and gotchas

- **Never read or print `/etc/openfortivpn/config`.** It is `0600 root` and holds credentials. The applet
  must keep working without access to it; do not add features that need its contents.
- **`libcosmic` is pinned by `rev`** in `Cargo.toml` to the revision used by `cosmic-applets`
  `epoch-1.10.0`. Do not switch to a branch/`master`. Upgrading means bumping `rev` and fixing API breaks;
  the reference implementation for API usage is `cosmic-applets` at the same tag
  (e.g. `cosmic-applet-a11y`, `cosmic-applet-bluetooth`).
- Proxy traits generated by `#[zbus::proxy]` must be `pub` (the generated types are used from `app.rs`).
- The D-Bus `Connection` returned by `systemd::watch()` must stay alive: systemd's `Subscribe()` is
  per-connection, and dropping it silently stops property-change signals.
- `Message` update arms return `app::Task<Message>`; use `cosmic::task::future(...)` for async work.
- Traffic stats come from sysfs counters (no root needed) and are polled every 2 s by a `time::every`
  subscription that exists **only while the popup is open and the state is `Connected`**. Keep it that way
  (no background polling). Uptime comes from the unit's `ActiveEnterTimestamp`.
- The `.deb` installs to `/usr` (`/usr/bin`, `/usr/lib/systemd/system`, `/usr/share/polkit-1/rules.d`,
  `/usr/share/applications`), while `install.sh` uses `/usr/local` and `/etc`. A new file in `data/` must be added to
  both `install.sh`/`justfile` and the `assets` list in `Cargo.toml`. `debian/postinst` deletes the exact files
  `install.sh` creates (so they do not shadow the package) — keep that list in sync with `install.sh`.
  The package must never ship or touch `/etc/openfortivpn/config`, and `prerm` stops the unit only on
  `remove`/`deconfigure`, never on upgrade (an update must not drop the user's VPN).
- The unit has no `[Install]` section on purpose (no autostart). The unit runs `openfortivpn` **without**
  `-c` so the default `/etc/openfortivpn/config` is used.
- The polkit rule must stay scoped to `action.lookup("unit") == "cosmic-fortivpn.service"`.
  Never widen it to other units or to all `manage-units` requests.
- The applet ID `com.github.artur.CosmicAppletFortiVpn` appears in `src/app.rs`, `justfile`, `install.sh` and the
  `.desktop` filename. Change all of them together; it is also the key stored in the user's panel config
  (`~/.config/cosmic/com.system76.CosmicPanel.Panel/v1/plugins_wings`).
- UI strings come from Fluent files in `i18n/<lang>/cosmic_applet_fortivpn.ftl` via the `fl!` macro
  (`src/localize.rs`). **English is the fallback** and the source of truth: add every new key to `en` first,
  then to every other language; a test checks that all languages have the same keys and `{ $placeholders }`. Never hardcode user-visible text in `src/app.rs`.
- `FluentLanguageLoader::set_use_isolating(false)` only affects already loaded bundles, so it must be called
  after every language load (done in `localize.rs`), otherwise Unicode isolation marks appear around arguments.
- `cargo` is not in root's `PATH` — build as the normal user, install with `sudo`.

## Testing changes

Unit tests cover the pure logic (`VpnState::from_active_state`, `parse_ip`). The UI and D-Bus parts need a
real COSMIC session with the unit installed:

1. `cargo build --release && sudo ./install.sh`
2. `systemctl start cosmic-fortivpn` / `stop` as a normal user must not ask for a password;
   starting an unrelated unit must still require authentication.
3. Add the applet in panel settings; toggle it and watch `ip -br a | grep ppp` and
   `journalctl -u cosmic-fortivpn`.
4. Change state from a terminal (`systemctl stop cosmic-fortivpn`) — the icon must update on its own.

Do not stop a user's running VPN, or trigger polkit prompts for unrelated units, without asking first.

## Releases

Bump `version` in `Cargo.toml` (and `Cargo.lock`), add a `CHANGELOG.md` entry (`## X.Y.Z - date`), commit and push to `main`.
When CI on `main` succeeds and `vX.Y.Z` does not exist yet, `release.yml` creates the tag and the GitHub release
(notes are taken from `CHANGELOG.md`; assets: `.deb`, `.tar.gz` and their `.sha256`) automatically — **do not**
push the tag by hand. Pushing to `main` without a version bump releases nothing. A manually pushed tag `vX.Y.Z`
still works; the workflow fails if it differs from the `Cargo.toml` version.
CI also builds the `.deb` and installs it in a clean `ubuntu:24.04` container (`scripts/test-deb.sh`) on every push and PR.
